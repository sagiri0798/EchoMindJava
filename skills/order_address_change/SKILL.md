# 订单收货地址变更规范

## 适用边界

仅用于订单收货地址变更。账单、退款、发票、订阅问题仍按账单规范处理，不得把地址流程混入资金处理。

## 必收字段

订单号、收件人姓名、手机号（11 位）、省/市/区、街道及门牌号。缺什么问什么，一次只问必要字段。调用工具时 phone 只传 11 位数字（不带空格或 +86），省/市/区/街道/门牌分别传，不要合并。

## 标准流程

1. 拿到订单号后先调用 `lookup_order` 核验订单是否存在、是否归属当前用户、是否已发货；同时收集收件人、手机号、省/市/区、街道门牌，缺什么问什么，不要为了凑字段而推迟核验。
2. 信息齐全后，复述“收件人 + 脱敏手机号 + 省市区街道门牌”让用户确认；不要替用户确认。
3. 用户明确确认后，调用 `update_shipping_address`，`confirmed=true`，参数必须与复述内容一致。`confirmed` 只是沙箱门；真实订单系统必须在服务端验证用户确认，不能照搬此沙箱实现。
4. 工具返回 `sandbox=true` / `real_order_modified=false` 时，只能说明演示沙箱已记录变更预演，不得声称真实订单已被修改；如需真实生效，使用“通过正式客服渠道在订单系统提交”，不要写“人工客服/转人工/无法处理”触发升级。如果 `update_shipping_address` 不可用，说明演示环境未开启写操作，请用户通过正式客服渠道提交，不要声称已修改。
5. 订单不存在或非本人：统一说明无法核验，不猜测、不泄露订单归属。
6. 已发货：拒绝直接修改，建议用户联系承运商或通过正式客服渠道申请物流拦截；不得声称本系统可以代为提交拦截申请，也不承诺拦截成功。
7. 工具失败或结果未知：如实说明未确认，不重复提交，建议人工核验。

## 安全边界

- 不索要密码、验证码、完整支付信息。
- 不在回复中展示完整手机号（包括与订单现有信息对比时），旧号码也必须脱敏。
- 不承诺真实物流拦截成功。
- 工具参数只来自用户明确提供的信息，不编造订单号、地址或收件人。
